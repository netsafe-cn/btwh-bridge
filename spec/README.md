# spec/ — cross-language contracts

Everything in this directory is a **machine-checked contract**, not documentation. Each file
is either generated by a tool or compared against one in CI, so a drift turns the build red
instead of quietly producing wrong data six months later.

| File | Written by | Checked by | Consumed by |
|---|---|---|---|
| `api_contract.json` | `python python/tests/test_contract.py --update` | same test, in CI | the Python library's own regression |
| `protocol_vectors.json` | same command | `test_contract` (Python) and the C++ side | `python/bosch_api.py`, `firmware/components/bosch_proto` |
| `mqtt.json` | by hand, reviewed like code | `python/tests/test_mqtt_contract.py` | `firmware/bridge` (publisher), `firmware/panel` and `integrations/` (consumers) |
| `profiles.json` | by hand, reviewed like code | `python/tests/test_profiles.py`, `gen_mqtt.py` cross-check, the proto self test | `firmware/bridge` via `gen_profiles.py` -> `proto/profiles_gen.h` and `gen_mqtt.py` -> net constants; `bosch_api.py` pinned by tests |

## Why the MQTT contract comes before the code

The bridge and the panel are separate applications that never share a line of source. If the
topic names and field semantics lived only in the bridge's headers, the panel would have to
be written by reading the bridge — and the two would drift the moment either changed.

Putting them in one JSON file means:

- the panel can be developed against a stub publisher with no bridge present
- a rename in the bridge fails CI until `mqtt.json` is updated and every consumer follows
- Home Assistant discovery, the panel UI and the Mi Home bridge all read the same field list

`mqtt.json` is `status: draft` until the first public bridge release ships. The bridge already
publishes against it — bench-verified end to end against a production Mosquitto on HAOS, twice
over the OTA path — so the flag is now a release gate, not a placeholder: the day it flips to
`stable` the same freeze rules as `api_contract.json` apply: additive only, breaking changes
need a major version.

## Regenerating

```bash
python python/tests/test_contract.py --update     # refresh api_contract + protocol_vectors
python python/tests/test_contract.py              # verify, no write
```

Only run `--update` after reading the diff. It is meant to record an intentional change, not
to silence a failure.
